# 模式 C：第一性原理

定位：帮用户**认识这件事**，不强制给方案。

## 1. 结果倒推

这件事成了，是什么样？写成**可观察的结果**："稿子能直接投出去"，不是"质量提升"。

## 2. 拆约束（这一节是核心）

把"不能改"的东西全列出来，逐条分类：

| 类别 | 长什么样 | 算不算硬约束 |
|---|---|---|
| 物理 / 数学 | 成本下限、算力上限、材料极限 | **硬** |
| 法规 / 合同 / 明文要求 | 必须过审、必须签的条款、导师或客户的硬性要求 | **硬** |
| 实测事实 | 测过的延迟、跑过的数据、踩过的坑 | **硬** |
| 惯例 / 类比 / 权威 | "行业都这么说""大佬说的""供应商报价" | **软** |

软约束要留下，必须给一条**能被推翻的理由**；给不出，就是可以动的。

## 3. 逐层剖

- **现象**：现在看到的是什么
- **机制**：为什么会这样（谁在驱动、卡在哪）
- **前提**：机制成立靠哪些假设

## 4. 最脆弱一层

哪条假设一崩，全盘皆输。**只指一条**，说清崩了会怎样。

## 5. 落点（必须给一句）

> 所以，这件事的关键变量是 ___。

再补一句：它是**可动的**（那就动它）还是**硬约束**（那就只能绕开或接受）。

没有这两句，等于拆完没结论。

## 退出条件

- 每个"不能改"都有分类，没有一条悬空
- 最脆弱的一层指得出，且能说清崩了的后果
- 落点那句写得出

## 失败分支

- 拆到一半发现缺事实 → 停下，列"要查的 3 个事实"，不硬推
- 用户要方案 → 先说"给方案会跳过认识"，问要不要继续
- 用户要的是安慰而不是认识 → 明说这个模式不提供
- 发现软约束其实是硬约束（比如"行业惯例"背后是法规）→ 立即改分类

## 禁止

- 把现象当本质
- 拆完只给哲学结论，没有可核对的前提
- 用"本质上就是……"开头，然后接一句谁都能说的话
